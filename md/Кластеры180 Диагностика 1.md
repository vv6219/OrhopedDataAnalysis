## Раздел 1. Архитектура и методология трехуровневой приоритезации диагностических методов

## Раздел 3. Архитектура интеграции в МИС и программные контракты

### 3.1. DDL-скрипт создания структуры таблиц в PostgreSQL
Для хранения расширенной спецификации с трехуровневой моделью диагностики в реляционную базу данных МИС импортируется следующая структура:

```sql
-- Создание перечисления уровней диагностического приоритета
CREATE TYPE diagnostic_priority_level AS ENUM ('HIGH', 'MEDIUM', 'LOW');

-- Таблица ортопедических клинических шаблонов (180 единиц)
CREATE TABLE IF NOT EXISTS clinical_orthopedic_templates (
    template_id        INTEGER PRIMARY KEY CHECK (template_id BETWEEN 1 AND 180),
    cluster_code       VARCHAR(32) NOT NULL,
    cluster_title      VARCHAR(128) NOT NULL,
    nosology_title     TEXT NOT NULL,
    icd10_code         VARCHAR(10) NOT NULL,
    is_urgent_redflag  BOOLEAN NOT NULL DEFAULT FALSE,
    clinical_tests     JSONB NOT NULL,
    diagnostic_plan    JSONB NOT NULL,
    cdss_rules         JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Индексы для сверхбыстрого контекстного поиска при открытии талона приема
CREATE INDEX idx_ortho_cluster ON clinical_orthopedic_templates (cluster_code);
CREATE INDEX idx_ortho_icd10   ON clinical_orthopedic_templates (icd10_code);
CREATE INDEX idx_ortho_redflag ON clinical_orthopedic_templates (is_urgent_redflag) WHERE is_urgent_redflag = TRUE;
CREATE INDEX idx_ortho_diag_gin ON clinical_orthopedic_templates USING GIN (diagnostic_plan);
```

### 3.3. Логика СППВР (Системы поддержки принятия врачебных решений) по приоритетам
1. **Приоритет 1 (ВЫСОКИЙ):** Автоматически предзаполняется в электронном направлении на диагностику при выборе диагноза из справочника МКБ-10. При попытке врача закрыть прием без назначения исследований 1-й линии МИС запрашивает обязательное обоснование отказа («Услуга выполнена ранее», «Категорический отказ пациента», «Наличие противопоказаний»).
2. **Приоритет 2 (СРЕДНИЙ):** Рекомендуется системой при повторном визите, если на фоне базовой терапии сохраняется болевой синдром $\text{ВАШ} \ge 4$, либо при первичном обращении, если нозология требует оперативного лечения (например, разрывы связок, менисков, сухожилий, компрессионные переломы).
3. **Приоритет 3 (НИЗКИЙ):** Активируется в интерфейсе МИС по кнопке «Расширенный дифференциальный поиск / Предоперационная высокотехнологичная подготовка» и не входит в базовую стоимость первичного приема по клинико-статистическим группам (КСГ) ОМС.
4. **Блокировки безопасности (Red Flags):** Для протоколов `ID #167` (Септический артрит), `ID #170` (PJI), `ID #179` (Синдром конского хвоста) и `ID #180` (Костная онкология) программно блокируются консервативные и физиотерапевтические назначения, а система выставляет статус экстренного направления `STAT / CITO`.
